# Terraform Stacks — AWS VPC Component

A **reusable Terraform Stack component** that provisions a production-ready, multi-AZ AWS VPC using workload identity (OIDC) authentication. This component wraps the [`aws-vpc`](./modules/aws-vpc) module and is designed to be referenced by a Terraform Stack as a foundational networking layer.

## What Is a Stack Component?

A Stack Component is a reusable building block for Terraform Stacks. It defines infrastructure (via a child module) along with its provider configuration and input/output contract. Components are consumed by a Stack's deployment configuration (`.tfdeploy.hcl`), which lives in a separate orchestration repository.

This repository contains the **component definition only** — no deployment configuration. To deploy, reference this component from a Stack orchestration repo.

## Repository Structure

```
.
├── .terraform-version                  # Required Terraform CLI version (>= 1.13)
├── .terraform.lock.hcl                 # Provider dependency lock file — always commit
├── components.tfcomponent.hcl          # Component definition (vpc)
├── variables.tfcomponent.hcl           # Stack input variables
├── outputs.tfcomponent.hcl             # Stack outputs
├── providers.tfcomponent.hcl           # AWS provider with OIDC workload identity
└── modules/
    └── aws-vpc/                        # Local Terraform module (no provider blocks)
```

## How to Use This Component

Reference this repository from a Stack orchestration repo's `components.tfcomponent.hcl`:

```hcl
component "vpc" {
  source  = "git::https://github.com/benoitblais-hashicorp-demo/terraform-aws-stacks-vpc.git"
  version = "~> 1.0"

  inputs = {
    vpc_name           = var.vpc_name
    vpc_cidr           = var.vpc_cidr
    single_nat_gateway = var.single_nat_gateway
    regions            = var.regions
    tags               = var.tags
  }

  providers = {
    aws = provider.aws.configurations[each.value]
  }
}
```

The deployment configuration (`deployments.tfdeploy.hcl`, identity tokens, `deployment_group`, auto-approve rules) belongs in the orchestration repo, not here.

## Authentication

Authentication uses **AWS OIDC workload identity** — no long-lived static credentials are stored. HCP Terraform generates an ephemeral JWT at runtime, which is exchanged for temporary AWS credentials via `assume_role_with_web_identity`.

For OIDC role setup see: <https://github.com/hashi-demo-lab/aws-openid-role-for-stacks>

## What Gets Deployed

One VPC per region specified in `var.regions`:

| Resource | Details |
|---|---|
| VPC | Custom CIDR, DNS enabled |
| Public Subnets | 3 subnets across 3 AZs, tagged for ELB |
| Private Subnets | 3 subnets across 3 AZs, tagged for internal ELB |
| Internet Gateway | Attached to VPC |
| NAT Gateway | One (configurable) for private subnet egress |
| Route Tables | Public and private routing |

## Required Inputs

| Name | Description | Type |
|---|---|---|
| `aws_identity_token` | Ephemeral OIDC JWT for AWS (auto-generated by HCP Terraform) | `string` |
| `role_arn` | ARN of the IAM role to assume | `string` |
| `vpc_name` | Name of the VPC | `string` |
| `vpc_cidr` | CIDR block (e.g. `10.0.0.0/16`) | `string` |

## Optional Inputs

| Name | Description | Type | Default |
|---|---|---|---|
| `regions` | AWS regions to deploy into | `set(string)` | `["ca-central-1"]` |
| `single_nat_gateway` | Use one NAT GW (cost-saving; not HA) | `bool` | `true` |
| `tags` | Additional resource tags | `map(string)` | `{}` |

## Outputs

All outputs are `map` values keyed by region.

| Name | Type | Description |
|---|---|---|
| `vpc_id` | `map(string)` | VPC ID per region |
| `vpc_cidr_block` | `map(string)` | VPC CIDR block per region |
| `private_subnets` | `map(list(string))` | Private subnet IDs per region |
| `public_subnets` | `map(list(string))` | Public subnet IDs per region |
| `route_table_id` | `map(list(string))` | Private route table IDs per region |

## Requirements

| Name | Version |
|---|---|
| Terraform CLI | >= 1.13 (Stacks GA) |
| HCP Terraform | Active organization with OIDC configured |
| AWS Provider | `~> 6.0` |
| AWS Account | Active, with IAM role for OIDC federation |
